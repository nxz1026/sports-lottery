## 必须改的 5 处（都不大，但都影响远端能否用）

1. **失败也要产一行**（原来只要求 `.empty` 标记）。判据：`errorCode != "0"` **或** `success != true`（实测失败响应**没有 `value` 键**，别按 value 取数）。产
   `{"kind":"error","topic":"…","snap_ts":"…Z","endpoint":"…","http_status":200,"collector_host":"…","payload":{"errorCode":"P0001","errorMessage":"参数不合法","emptyFlag":false,"dataFrom":null},"src_hash":"…"}`。
   远端要靠它区分**"该期真的没比赛"**和**"参数错了/接口坏了"**——两者在 HTTP 层都是 200，只看 `.empty` 分不出来。
2. **`snap_ts` 全 topic 必填，UTC 带 `Z`，＝请求发出时刻**（原 §5 只在 `jczq_offer` 要求）。官方自带的更新时间（`oddsList[].updateDate/updateTime`、`value.lastUpdateTime`）**留在 payload 里**，不许拿它当 `snap_ts`。
3. **payload 一律官方键名原样，不许改名/清洗/判奖**。举例（都会成为远端解析依据）：`lotterySaleEndtime`（官方就少一个 a，照抄）、`stakeAmount:"12,387"`（带千分位，照抄）、`jqc` 的 `result:"3＋,1"`（**全角加号**，照抄）、`jczq_result.sectionsNo999:"取消"`（中文，照抄，**别跳过这行**）、篮彩 `finalScore:"61-105"`（连字符）。
4. **`jczq_offer`/`jclq_offer` 的快照节奏改成每 10 分钟一次**（§5.8，原 §6 的四个整点保留）。这不是加负载：同一 `matchId` 的多条快照就是盘口时序，**封盘前最后一条＝远端认定的收盘价**，是 CLV/期望值唯一可信来源。远端靠它省掉一整笔境外盘口 API 开销。
5. **`src_hash` 必须按官方式子算**：`sha256(json.dumps(payload, ensure_ascii=False, sort_keys=True, separators=(",",":")).encode("utf-8")).hexdigest()`。远端拿它做幂等键，手拼字符串会导致重复入库。
