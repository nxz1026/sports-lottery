# 玩法覆盖分析报告 v2 变更记录（2026-09-15 晚）

本文仅记录 v1 之后的**范围与架构变更**，v1 正文保留作历史。

## 变更 1：玩法范围最终锁定
- 竞彩足球 6 玩法 × **6 联赛**：英超、西甲、意甲、德甲、法甲、**中超**
- 竞彩篮球 3 玩法（胜负/让分/大小）× **NBA、CBA**（CBA 盘口覆盖待实测，先上"比分+预测"）
- 传统足彩 4 玩法：14场 / 任9 / 6场半全场 / 4场进球 —— **奖期圈选自动化升级**：官方奖期表由国内采集机推送（不再需要人工核对圈选）
- 数字彩 4 种：大乐透、排列3、排列5、七星彩 —— 定位=管理+组合数学+EV+回测器+AI参考号，不承诺预测
- 不定期赛事：世界杯 / 欧洲杯 / 欧冠 / 亚冠 → **数据驱动的开关窗口**（ref.league.window），到点自动激活，模型特化（中立场去主场加成；欧冠 36 队新赛制需扩展蒙特卡洛对阵结构）
- ❌ 北京单场：移除（浮动 SP + 无合法接口）
- ❌ 乐透之外（7星彩/胜负游戏等）不在列

## 变更 2：AI 定位修正
LLM 可以产出数字（参考性质、合法），展示层必须打来源标签（`ai_ref` vs `model`）；AI 数字不进 EV/CLV 计算链，只进报告与票面建议。

## 变更 3：博彩盘口升为核心数据（用户判定"非常重要"）
- 新增**盘口时序**：每场"开盘 + 临场收盘"两个快照点，仅采竞彩开售场次（免费档配额约束下的既定分配）
- 新算法件：锐利庄加权去水（Pinnacle 等）、CLV（模型 vs 收盘）、赔率分歧/steam 特征、竞彩官方 SP × 国际收盘错位 → EV 报告
- 现有"市场权重 45%"从单一平均升级为锐利庄加权

## 变更 4：数据底座 = Oracle PG 18.6（nd-oracle，127.0.0.1:5432）
FastAPI Cloud 平台退役（框架是否保留见决策项 D1）。所有取数/预测/开奖/官方数据统一入库；详见《数据库设计-v2》。

## 变更 5：国内采集机模式
竞彩官方 + 传统足彩 + 数字彩开奖由**国内机采集器**（用户侧 AI 实施）产出 CSV → rsync over SSH → oracle `/srv/league/incoming` → ingest 定时任务 UPSERT 入库。采集器只走官网 JSON 网关接口，不页面解析、不直连数据库。详见《国内采集机实施文档》。

## 变更 6：串关形态
推荐组合 + EV 报告（含单关资格字段 `jc_price.single`），不做投注单 UI。
